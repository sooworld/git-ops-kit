# 운영 프로필과 프로젝트 유형

설치되는 `docs/GIT.md`는 1인 승인자와 여러 에이전트를 기본으로 쓴다. 이 문서는 승인자가 여러 명일 때 달라지는 점과, 프로젝트 유형별로 채울 값의 예를 둔다. 예는 출발점일 뿐이므로 저장소에 맞게 고친다.

## 운영 프로필

### 1인 승인자

GIT.md 그대로 쓴다. 승인자 한 명이 모든 PR을 판정하고 병합한다. 독립 검수는 작성자가 아닌 새 맥락의 에이전트가 한다. 공유 진행 목록은 그 사람의 clone 안에서만 쓴다.

### 팀

승인자가 여러 명이고 사람 리뷰가 있는 경우다. 다음이 달라진다.

- **판정 담당**: 경로별 승인자를 CODEOWNERS에 적는다. 고위험 경로(GIT.md '위험 등급')는 반드시 담당을 둔다.

  ```text
  # .github/CODEOWNERS 예
  /.githooks/            @org/platform
  /scripts/gitops/       @org/platform
  /tests/gitops/         @org/platform
  /gitops.config.json    @org/platform
  /AGENTS.md             @org/leads
  /docs/GIT.md           @org/leads
  /docs/adr/             @org/leads
  ```

- **서버 보호**: 팀 저장소는 유료 플랜이나 공개 저장소인 경우가 많다. 보호 브랜치에 "PR 필수", "필수 리뷰 1명 이상", "CODEOWNERS 리뷰 필수", 필수 검사 `guard-checks`(워크플로 gitops guards의 작업)를 켠다. 그러면 로컬 장치는 실수를 일찍 알려 주는 보조가 된다. 이 사실을 ADR-0001 '맥락'과 GIT.md '장치와 한계'에 적는다.
- **독립 검수**: 사람 리뷰어가 요청·기준 문서·diff를 읽고 PR 본문과 대조하면 그것이 독립 검수다. 이때 검수 에이전트는 선택이다. 고위험 PR은 사람 리뷰와 검수 에이전트를 둘 다 두는 것을 권한다.
- **병합**: 승인자 누구나 병합할 수 있되, 에이전트는 병합하지 않는다는 규칙은 그대로다. 병합 방식은 저장소 설정으로 하나만 켠다.
- **공유 진행 목록**: `.git/coordination/active.md`는 clone 하나 안의 로컬 색인이라 다른 사람에게 보이지 않는다. 사람 사이의 조정은 draft PR, Issue, 팀 보드처럼 모두가 보는 곳에서 한다. 각자의 clone 안에서 여러 에이전트를 돌릴 때만 로컬 목록을 쓴다.
- **pre-push**: 사람도 보호 브랜치에 직접 push할 수 없다. 긴급 수정도 PR로 한다. 관리자의 직접 push가 꼭 필요하면 그 절차를 ADR로 정한다.

## 프로젝트 유형

각 유형에 위험 등급의 '프로젝트 경로', `.gitignore` 추가 줄, 비밀 패턴 추가 예, '프로젝트 규칙' 예를 둔다. 비밀 패턴은 `gitops.config.json`의 `commit.secretPatterns`에 더한다(JSON 안에서는 `\`를 `\\`로 쓴다).

### 웹 애플리케이션

| 등급 | 프로젝트 경로 | 승인자가 읽을 것 |
|---|---|---|
| 고위험 | 인증·권한(`src/auth/**`), 결제, DB migration(`migrations/**`, `prisma/**`), 배포·인프라 설정(`infra/**`, `Dockerfile`, `.env.example`), 요구 기준 문서 | diff 전체 |
| 중위험 | 앱 코드(`src/**`), 테스트 | 바뀐 함수와 그 테스트 |
| 저위험 | 문서, 스타일, 생성 파일(`*.snap`, lock 파일 갱신만) | 본문 두 칸 |

- `.gitignore`: `node_modules/`, `dist/`, `build/`, `coverage/`, `.env.local`
- 비밀 패턴 예: `\bsk_live_[A-Za-z0-9]{20,}`(결제 키), `[a-z]+://[^:/\s]+:[^@/\s]+@`(비밀번호가 든 접속 URL)
- 프로젝트 규칙 예:
  - 외부 시스템 보호: 운영 DB와 운영 환경 변수에 접근하지 않는다. 스테이징만 쓴다. migration 실행과 외부 결제 API 호출은 실행 전에 확인한다.
  - 작업별 검증: 단위 테스트, 타입 검사, 바뀐 화면의 수동 확인. 실행하지 못한 E2E는 미실행으로 적는다.

### 라이브러리

| 등급 | 프로젝트 경로 | 승인자가 읽을 것 |
|---|---|---|
| 고위험 | 공개 API 진입점(`src/index.*`), 패키지 메타데이터(`package.json`, `pyproject.toml`), 릴리스 설정, 라이선스 | diff 전체 |
| 중위험 | 내부 구현, 테스트 | 바뀐 함수와 그 테스트 |
| 저위험 | `docs/**`, `examples/**`, CHANGELOG 문구 | 본문 두 칸 |

- `.gitignore`: `dist/`, `build/`, `*.tgz`, `*.egg-info/`
- 비밀 패턴 예: `\bnpm_[A-Za-z0-9]{36}\b`(npm 토큰), `\bpypi-[A-Za-z0-9_-]{50,}`(PyPI 토큰)
- 프로젝트 규칙 예:
  - 외부 시스템 보호: 패키지 배포(`npm publish`, `twine upload`)는 에이전트가 하지 않는다. guard는 이 명령을 막지 않으므로 이 규칙과 도구 권한 설정(Claude Code `permissions.deny` 등)으로 막는다.
  - 작업별 검증: 공개 API가 바뀌면 semver 판단과 CHANGELOG 항목을 PR 본문에 적는다.

### 문서·기획 저장소

| 등급 | 프로젝트 경로 | 승인자가 읽을 것 |
|---|---|---|
| 고위험 | 요구 기준 문서(요구사항·합의 원본), 작업 원장의 결정·안전 규칙 절 | diff 전체 |
| 중위험 | 산출물을 만드는 스크립트 | 바뀐 문단·함수 |
| 저위험 | 분석·조사 산출물, 원장의 나머지 절(관찰·작업 로그) | 본문 두 칸 |

- `.gitignore`: 세션 쿠키·토큰이 섞일 수 있는 원본 자료(`*.har`, 브라우저 저장 파일, `evidence/raw/` 같은 폴더)
- 비밀 패턴 예: 조사 대상 사이트의 세션 키 이름에 값이 붙은 형태(예: `session_id["':= ]+[A-Za-z0-9]{16,}`)
- 프로젝트 규칙 예:
  - 작업별 시작 문서: 작업 원장의 범위·확정된 결정·안전 규칙·최신 인계를 읽고 시작한다.
  - 외부 시스템 보호: 조사 대상 사이트에서 저장·제출·설정 변경을 하지 않는다.
- 한 파일 안의 절마다 등급이 다르면 경로 규칙으로 구분되지 않는다. 작성 에이전트가 PR 본문 '위험 등급'에 바뀐 절을 적고 독립 검수가 확인한다.

## 고른 뒤

1. 고른 유형의 표를 `docs/GIT.md` '위험 등급' 표의 '프로젝트 경로' 자리에 옮기고 `TODO(gitops)` 표시를 지운다.
2. 프로젝트 규칙 예를 `AGENTS.md` '프로젝트 규칙'에 맞게 고쳐 넣는다.
3. `.gitignore` 줄과 비밀 패턴을 더한 뒤 `node scripts/gitops/setup.mjs --check`와 `node --test "tests/gitops/*.check.mjs"`를 돌린다.
4. 팀 운영이면 CODEOWNERS와 서버 보호를 켜고 ADR-0001에 적는다.
