# 공통 에이전트 지침

이 저장소의 공통 지침은 이 파일에서 관리한다. CLAUDE.md는 이 파일을 가져오는 진입점이다. 지침을 고칠 때 판단 근거는 커밋 메시지의 '배경'·'결정과 버린 대안'에 남긴다.

- 목적: 이 저장소가 관리하는 것과 관리하지 않는 것.

- 작업별 검증: 코드·문서·데이터 변경마다 실행할 검사와, 실행하지 못했을 때 남길 것.

## 작업 기준

- 기록된 관찰·버전·환경 조건은 날짜와 근거를 확인한다. 과거 관찰을 현재 사실로 단정하지 않는다.
- Git 작업은 docs/GIT.md를 따른다. 요구와 유효 ADR이 충돌하거나 범위·권한·저장 데이터에 영향을 주는 미정 사항이 있으면 사용자에게 확인한다. 이미 승인된 범위 안의 통상적인 선택은 진행한다.
- 시작할 때 branch·HEAD·미커밋 상태·규칙 기준 SHA와 관련 진행 작업을 확인하고, 인계의 현재 상태 블록을 읽어 공유 목록·PR 상태와 대조한다. 공유 목록의 위치와 등록은 docs/GIT.md '시작과 공유 진행 목록'을 따른다. 미병합 제안을 현재 권한으로 해석하지 않는다.

## 범위와 외부 시스템 보호

- 승인된 작업 범위 밖의 기존 동작·데이터와 사용자의 미커밋 변경을 보존한다. 요구를 범위에서 빼거나 접근 권한·저장 데이터·기능 유무에 관한 주요 가정을 새로 정해야 하면 사용자에게 확인한다.
- 외부 시스템은 위 '프로젝트 규칙'의 범위 안에서만 다룬다. 공유 서버·운영 데이터의 설정과 내용을 임의로 바꾸지 않는다. 조회에 따른 부수 쓰기는 기록하고, 생긴 데이터를 임의로 지워 복구하지 않는다.
- 근거 파일·문서·커밋 메시지에 실제 비밀 값(키·토큰·비밀번호·세션 쿠키)과 개인정보 값을 남기지 않는다. 필드 이름이나 마스킹된 예시는 금지 대상이 아니다.
- 커밋 전 staged diff에서 실제 비밀 값과 개인정보를 확인한다. .gitignore와 commit-msg 훅은 이 검토를 대체하지 않는다.

## 구현과 변경 판단

- 현재 요구를 충족하는 가장 단순한 구현을 선택한다. 추측한 미래 요구를 위한 추상화·설정·간접 계층은 추가하지 않는다.
- 동작하고 검증 가능한 작은 변경을 완성하면서 확장한다. 책임을 분리하고, 임시 조치가 필요하면 이유·위험·제거 조건을 기록한다.
- 불필요한 호환 계층·fallback은 추가하지 않는다. 승인된 변경에서 호환성을 제거하거나 데이터를 이전해야 하면 외부 계약·데이터 영향을 확인하고 검증 방법을 명시한다. 모든 migration을 일괄 금지하지 않는다.
- 기존 도구·의존성이 필요한 기능을 제공하는지 먼저 확인한다. 새 라이브러리는 직접 구현보다 전체 복잡도나 신뢰성을 개선할 때 도입한다.
- 새 스크립트의 목적·입출력·중요한 부수 효과는 파일 머리에 적고, 함수는 이름과 타입으로 알기 어려운 제약을 설명한다.

## 검증·Git·인계

- Git 운영 도구·훅·CI 변경은 docs/GIT.md '장치와 한계'에 적힌 검증 명령으로 검증한다. 명령이 아직 없으면 실행한 확인과 미실행을 구분해 적는다. 문서만 바꾸면 참조·중복·상충·민감정보를 점검한다.
- 로컬 테스트 통과가 실제 동작이나 GitHub CI 성공을 증명한다고 쓰지 않는다. 검증한 커밋 SHA와 이후 미커밋 변경을 구분해 남긴다.
- 하나로 받아들이거나 되돌릴 수 있는 완료 목표당 담당자·브랜치·PR 하나를 기본으로 한다. 같은 승인 범위의 하위 작업만 묶고 병렬 에이전트는 worktree를 분리한다.
- 조정 담당 에이전트 한 명이 공유 진행 목록을 갱신하고 범위·의존 변경을 관련 담당자에게 전달한다. 새 결정 질문은 모아서 제시한다. 의존 대기는 docs/GIT.md '인계와 의존 작업'에 따라 독립 작업을 진행한다.
- 보호 브랜치(gitops.config.json `protectedBranches`)에 직접 push하지 않고, 훅을 우회하지 않고, PR을 병합하지 않는다. 모든 PR은 사람이 병합한다. PR 본문에 docs/GIT.md '위험 등급'을 적어 사람이 어디까지 읽을지 알 수 있게 한다. 로컬 훅만으로 모든 우회를 막는다고 주장하지 않는다.
- 이미 낸 PR의 브랜치에 커밋을 더 push하기 전에 PR 상태를 확인한다(docs/GIT.md 'PR').
- Git 운영 장치를 더하거나 고칠 때는 docs/GIT.md '목적과 범위'(기록·판정 지점·되돌림, 실수 방지)에 들어가는지 먼저 확인한다. 들어가지 않으면 더하지 않는다.
- PR 본문은 판정용 양식(.github/pull_request_template.md)으로 쓴다. 병합 판정 전에 작성자가 아닌 새 맥락의 검수 에이전트가 요청·기준 문서·diff·근거를 먼저 읽고 본문과 대조한다. 검수 base/head SHA와 지적·미확인을 남긴다.
- 커밋에는 변경 당시 이유·선택·검증을 남기고 .gitmessage를 따른다. 장기 결정은 ADR에 상태와 대체 관계를 기록한다.
- 진행 상황은 인계나 새 댓글 초안에 남긴다. 최종 범위·근거·검증 SHA는 PR의 해당 칸만 갱신하고 이전 검수 SHA를 보존한다. 외부 댓글 전송에는 사용자의 명시적인 요청이 필요하다.
- 종료·인계 때 한 일·다음 행동·막힌 것·검증 SHA와 결과·미커밋 상태·외부 효과·의존 작업을 남기고, 인계 맨 위의 현재 상태 블록을 덮어써 갱신한다(docs/GIT.md '인계와 의존 작업'). 이전 담당자의 쓰기 종료 후 인계하며 종료 표시·삭제 조건은 docs/GIT.md '종료와 작업 공간 정리'를 따른다.

## 결과 작성

- 독자가 판단하는 데 필요한 조건·주체·대상·행동을 명확하게 쓴다. 문장은 짧게 쓰되, 생략 때문에 해석이 갈리지 않게 한다.
- 결론에는 확인한 사실·추론·미확인을 구분하고 근거 위치를 붙인다.
- 문서를 참조할 때 파일명과 절 제목 또는 작업 ID를 쓴다. 위치가 바뀌는 절 번호만으로 참조하지 않는다. 과거 위치를 특정해야 하면 커밋 SHA를 함께 남긴다.
- 변경 내용·이유·검증 결과·남은 한계를 보고하고, 수행하지 않은 작업을 완료한 것으로 쓰지 않는다.
